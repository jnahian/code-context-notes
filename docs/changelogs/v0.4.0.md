# Changelog - Version 0.4.0

## [0.4.0] - 2026-07-18

v0.4 ships **`@jnahian/code-notes-mcp`**, a standalone MCP server that gives any MCP-capable agent (Claude Code, Cursor) read/write access to workspace notes. Extension internals move into a shared **`@jnahian/code-notes-core`** package; extension behavior is unchanged.

### Added
- **`@jnahian/code-notes-mcp` — standalone MCP server** (stdio transport)
  - **Read tools:** `search_notes`, `get_notes_for_file`, `get_notes_for_changes` (pre-edit context), `list_instructions`, `get_handoffs`, `get_note`
  - **Write tools:** `create_note`, `edit_note`, `delete_note`, `add_handoff`, `add_decision` — hidden and rejected unless started with `--agent <name>`
  - **Resources:** `code-notes://digest`, `code-notes://index`, `code-notes://file/{path}`
  - **Concurrency:** per-note advisory file locks (`.code-notes/.locks`) shared with the extension; writers re-read inside the lock, so a concurrent edit is never overwritten
  - **In-band JSON errors** for every failure (`invalid_arguments`, `lock_timeout` retryable, `path_escapes_workspace`, `references_required`, …) — tool and resource failures never surface as JSON-RPC protocol errors
  - **`--storage-dir`** matches a customized `codeContextNotes.storageDirectory`; **`--require-existing`** refuses to start without a `.code-notes/`

### Changed
- **Repo is now an npm workspaces monorepo** — the extension lives at `packages/extension/`
- **Shared `@jnahian/code-notes-core`** — extension internals extracted behind vscode-decoupled interfaces so both hosts run one implementation

### Fixed
- **Lost update / data loss** — `updateNote`/`deleteNote` did their read-modify-write against a process-local cache inside the lock, so a long-lived server with a warm cache could silently erase an edit from a note's history. Both now re-read from storage inside the lock.
- **Sidebar now shows agent-created notes** — the cache clear missed the workspace-wide caches, so externally-written notes stayed hidden until the next edit
- **Stale reads** on the MCP tool and resource surfaces — the watcher-less server now drops caches per dispatch and per resource read
- **Malformed resource URIs** (e.g. a lone `%`) and mid-read I/O errors now return in-band errors instead of a JSON-RPC protocol error
- **Diff line ranking** — `get_notes_for_changes` no longer counts `\ No newline at end of file` markers as lines, which had shifted matched line numbers

### Compatibility
- Extension behavior unchanged; existing workspaces work without modification
- MCP server reads/writes the same `.code-notes/` directory the extension uses

### Testing
- 376 tests across packages: core 107, MCP server 74 (including cross-process extension-vs-MCP race, lock-contention, stale-cache, malformed-URI, and diff-marker regression tests), extension 19 unit + 176 integration
- Full stdio end-to-end smoke against the built server (create/decision/search/changes/resources/delete) verified green

### Technical
- Monorepo layout: `packages/extension`, `packages/code-notes-core`, `packages/code-notes-mcp`
- MCP server built on `@modelcontextprotocol/sdk`; all logging on stderr, stdout reserved for JSON-RPC
- Advisory lock files (`.code-notes/.locks/<id>.lock`, exclusive create, 500ms acquire timeout, stale >60s broken) guard writes in both hosts
- Shared `resolveInWorkspace()` path guard rejects workspace-escaping paths on both write tools and the file resource

### Coming Next
- v0.5 ships the trust model (`audit` / `queue` / `direct` modes) and the agent activity sidebar
