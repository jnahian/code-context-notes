# Changelog - Version 0.5.1

## [0.5.1] - 2026-07-22

A small privacy default: a new `.code-notes/` directory is now created with its own `.gitignore`, so notes stay local until you decide to share them.

### Added
- **Self-ignoring `.code-notes/.gitignore`** — written once, when the storage directory is first created. It ignores everything in the folder (including itself) and carries a two-line comment telling you to delete the file if you'd rather commit your notes and share them with your team.

### Changed
- Notes are untracked by default in new workspaces. Existing workspaces are untouched — the file is only written when the storage directory is created, so deleting it keeps it deleted.

### Testing
- Storage manager suite covers both halves of the behavior: the file is written on first creation, and it is not recreated on a later `createStorage()` after being deleted.

### Technical
- `StorageManager.createStorage()` keys off the return value of `fs.mkdir(..., { recursive: true })`, which is `undefined` when the directory already existed — so the write is genuinely first-run-only, not an `exists?` race.
