# Changelog - Version 0.5.0

## [0.5.0] - 2026-07-18

v0.5 puts you in control of agent-authored notes. One workspace setting — **`codeContextNotes.agentWriteMode`** — decides how writes from MCP agents are handled: land immediately (`direct`), land and get logged (`audit`, the new default), or wait for your approval (`queue`). Two sidebar views let you review and undo agent activity.

### Added
- **Agent write modes** (`codeContextNotes.agentWriteMode`: `direct` | `audit` | `queue`)
  - Stored in `.code-notes/config.json` so the standalone MCP server reads the same policy — the VS Code setting is just its UI. There is deliberately **no server flag** for the mode: an agent that picks its own rails has none. The server re-reads it per call, so a change takes effect with no restart.
- **`audit` mode + Agent activity view**
  - Every agent op appends to `.code-notes/_audit.log` (JSONL) without blocking the write; the log rotates atomically to `_audit.log.1` past `auditLogRetention`, losing no entry even under concurrent writes from several agents.
  - The **Agent activity** sidebar lists recent ops with inline **Revert** (create→delete, edit→prior content, delete→restore), **Open note**, and a `Code Notes: Truncate Audit Log` command.
- **`queue` mode + Pending agent proposals view**
  - Agent writes never touch live notes — each becomes a proposal in `.code-notes/_pending/`, and write tools return `{ "status": "pending", proposalId }` (a success shape, not an error, so agents don't retry-loop).
  - The **Pending agent proposals** sidebar offers **Approve / Reject / Edit-and-approve**: Approve attributes the note to you and records `approvedBy`; Reject moves the file to `_pending/.rejected/` for audit. A note edited since its proposal triggers a simple-pick (yours vs. the agent's); an orphaned proposal (target note gone) can only be rejected; leaving `queue` mode with proposals pending prompts to review or reject them.

### Settings
- **`codeContextNotes.agentWriteMode`** — `direct` | `audit` | `queue` (default `audit`), mirrored to `.code-notes/config.json`
- **`codeContextNotes.agentAllowList`** — informational list of agent names (not a security boundary)
- **`codeContextNotes.auditLogRetention`** — entries kept before rotating to `_audit.log.1` (default 1000)

### Fixed
- **Reverting an agent edit restores the right version** — Revert now finds the replaced content by the audit entry's `prevContentHash` instead of by history position, so reverting an edit that isn't the note's latest change (a later agent or human edit landed on top) no longer restores the wrong content.
- **Reverting an agent delete works** — a soft-deleted note's content survives, and Revert now restores it, where an earlier cut couldn't see or restore the deleted note.
- **Note repositioning locks and re-reads** (carried from v0.4) — following an editor's document changes could overwrite a note edited concurrently by another process; it now re-reads inside the lock.
- **Empty-content notes survive reload** instead of vanishing, while a note file with a genuinely missing content section is still rejected as corrupt.
- **Approved edits are attributed** — approving an agent's queued *edit* records `approvedBy`, matching an approved create.
- **A restore is named as such** — reverting an agent's delete records history action `restored` rather than disguising it as an `edited` entry.
- **All sidebar sort options are selectable** — `sidebar.sortBy` declared only `file` in its setting enum, so the Settings dropdown never offered `date` or `author` even though the sidebar honored both; all three are now listed.

### Security
- **Agent-write identity comes from the writer, not the note** — in `queue` mode an agent could previously edit or delete any *human*-authored note with no approval, because the rails keyed off the note's author. Identity is now a property of the writer (server = agent, extension = human) and fails closed.
- **Note content can no longer forge note structure** — content is agent-controlled input, and the on-disk markdown used unescaped delimiters, so a body of `**Status:** DELETED` or `## Edit History` could delete the note or forge history on reload (poisoning Revert). Storage is now a versioned, length-delimited format.
- **The audit log never drops an entry under load** — rotation is atomic (rename, not rewrite) and appends are lock-free.
- **A proposal's `file` value can't split its frontmatter** — `file` is agent-controllable via `create_note`; a newline plus `---` could close the frontmatter early and hijack the fields below, so free-text scalars are now JSON-encoded.

### Compatibility
- **`audit` is the new default — a behavior change for upgraders.** A workspace that already has notes gains a `.code-notes/config.json` and starts logging agent writes to `.code-notes/_audit.log`; set `agentWriteMode` to `direct` for the pre-v0.5 behavior. A workspace with no notes is untouched until it has some.
- **Notes migrate to a new on-disk format (`**Format:** 2`) on next save** — existing notes are read by the untouched legacy parser and stay unchanged until re-saved; no manual migration.
- **Upgrade the MCP server alongside the extension** — a v0.4 server against a v0.5 workspace ignores `config.json` and behaves as `direct`.

### Testing
- 446 tests across packages: core 168, MCP server 76, extension 24 unit + 178 integration
- Independent trust-boundary audit plus adversarial injection tests (content forging `## Edit History` / `**Status:**`, history-fence breakout, proposal-frontmatter injection), a frozen v1-note migration gate, cross-process audit-log race tests, and mutation-checked regression guards for every security fix — including reverting a non-latest agent edit

### Technical
- **Trust routing lives in `@jnahian/code-notes-core`** — `NoteManager` consults a per-call `agentWriteMode` and routes agent writes to `AuditLog` (audit), `ProposalStore` (queue), or straight through (direct); detection is the writer's identity, never author-string sniffing
- **Versioned storage format** — v2 length-delimits the content region (`**Content Lines:** N`) and each history entry (` ```lines=N `) so agent-controlled text can never be re-parsed as structure; the untouched v1 parser reads pre-v0.5 notes
- The extension mirrors its settings into `config.json`, and its `.code-notes/` watcher routes `_pending/` and `_audit.log` to the new views instead of the note cache
